# 拉密（Rummikub）微信小游戏

基于**微信小游戏**（canvas 2D）实现的拉密游戏。核心游戏逻辑与界面完全分离：`js/core/` 是零依赖的纯 JS 模块，界面层只负责把状态画出来、把点击转成逻辑调用。

## 快速开始

1. 打开 **微信开发者工具** → 导入项目 → 目录选择本仓库根目录 `rammi-game`。
2. **项目类型必须选「小游戏」**。AppID 目前是 `wxc8166115ca830c9f`，正式发布前换成你自己的小游戏 AppID。
3. 点击「编译」，模拟器出现首页：点「开始游戏」→ 点「摸牌」→ 选牌 →「出牌」→「结束回合」，另外 3 家由 AI 自动行动。首页的「玩法说明」可以看规则速览。

> 如果之前曾以「小程序」类型打开过这个目录，工具会缓存旧的项目类型，表现为报错 `game.json: 未找到 game.json 文件`（或反过来找 `app.json`）。此时把项目从列表里移除后重新导入、并确认类型为「小游戏」即可。

本地跑纯逻辑测试（不依赖微信环境、不依赖第三方库）：

```bash
node tests/core.test.js
```

## 目录结构

```
rammi-game/
├── game.js                        // 小游戏入口（require ./js/main）
├── game.json                      // 小游戏运行时配置（竖屏等）
├── project.config.json            // 开发者工具项目配置（compileType: "game"）
├── js/
│   ├── core/                      // 纯游戏逻辑，零 wx 依赖，可在 node 下测试
│   │   ├── tiles.js               //   牌模型、106 张牌堆、洗牌、计分
│   │   ├── rules.js               //   顺子/刻子合法性、首出 30 分规则
│   │   ├── game.js                //   对局状态机：发牌、摸牌、出牌、结算
│   │   └── ai.js                  //   电脑玩家（贪心找牌组）
│   ├── ui/                        // canvas 界面层
│   │   ├── theme.js               //   颜色/圆角主题
│   │   ├── widgets.js             //   圆角矩形、画牌、按钮、命中判定
│   │   ├── home-scene.js          //   首页场景
│   │   ├── game-scene.js          //   对局场景
│   │   └── app.js                 //   场景管理 + 触摸分发
│   └── main.js                    //   创建画布、启动 requestAnimationFrame 主循环
└── tests/core.test.js             // 纯逻辑单元测试
```

分层的意义：`js/core/` 完全不碰 `wx.*`，所以规则可以在 Node 里跑测试、可以复用到云函数做服务端校验。改规则只动 core，改画面只动 ui，互不影响。

## 已实现 / 待实现

已实现：

* 106 张牌堆（4 色 × 1~13 × 2 套 + 2 张百搭），每人 14 张手牌。
* 摸牌 → 出牌 → 结束回合的完整回合流程。
* 顺子（同色连续 ≥3 张）与刻子（同数字、不同颜色 3~4 张）判定，支持百搭。
* 首次出牌非百搭点数之和 ≥ 30 的限制。
* 出完手牌获胜；牌堆摸空且所有人过牌后，手牌点数最低者获胜。
* 3 家简易 AI、首页与对局两个场景、点击选牌。

待实现（后续迭代方向）：

* **重排桌面已有牌组**（拉密的灵魂，目前打出去的牌不能再动）。
* 百搭的挪动与替换。
* 手牌拖拽摆放、出牌动画、音效、可出组合提示。
* 更强的 AI 策略、联网对战。

## 从哪开始开发

建议按「先规则、再交互、后联网」的顺序推进：

1. **先玩通现有流程**：导入后编译，跑一遍摸牌/出牌/结算，确认环境没问题。
2. **补全核心规则**（`js/core/`，最该先做）：实现重排桌面牌组与百搭挪动；每加一条规则，就在 `tests/core.test.js` 里补一个用例。
3. **打磨交互**（`js/ui/`）：现在是点击选牌 + 按钮，可升级为拖拽摆放、动画、牌组高亮。
4. **提升 AI 难度**（`js/core/ai.js`）：现在是贪心算法，可换成搜索/启发式。
5. **联网对战**：小游戏端接 `wx.connectSocket` 或云开发（CloudBase），把对局判定放服务端，直接复用 `js/core/`。

## 小程序 vs 小游戏

两者是微信里**并列的两种产品形态**，同一平台、不同项目类型，同一个文件夹不能同时是两者：

| 项目 | 小游戏（当前） | 小程序 |
| --- | --- | --- |
| 入口 | `game.js` | `app.js` |
| 配置 | `game.json` | `app.json` |
| 界面 | canvas 手绘 | WXML + WXSS 页面 |
| 项目类型 | `compileType: "game"` | `compileType: "miniprogram"` |

本项目的 `js/core/` 与形态无关，如果以后要改成小程序，只需要重写 `js/ui/` 这一层。
